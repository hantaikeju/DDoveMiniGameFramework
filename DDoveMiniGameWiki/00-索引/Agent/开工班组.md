# 开工班组

Concept ID：`/00-索引/Agent/开工班组`。地图：[Agent 总览](/00-索引/Agent/Agent总览.md)。接在 [需求稿工作流](/00-索引/Agent/需求稿工作流.md) 第 3 步。结论与代码冲突以当前代码为准。

目的：多子代理隔离上下文，父会话保持干净。不另开 `/ddove-crew`，不加编排者开环。用户入口仍是 `ddove-work`。不要直接 `/ddove-plan` / `/ddove-worker` 问答。问答 / 排障不写篇、不进班组，也不问选哪一篇。

拆图 / 工人 / 审查 / 评分已落 `.cursor/agents/` 与 `ddove-work` 角色卡。

外库 `feature-*` 只学交还协议与上下文隔离，不拷 8 圈编排、单切片串行、热更/导表/Prefab 禁令。

## 目标 / 不做什么

**要**

- 处理中 = `05-需求` 且 `draft` 且 `tags` 含 `需求`。`ddove-work` 的「改代码」分支不数稿：只拆本条对话当前 grill 的那一篇（`/ddove-grill` 刚落的稿，或 `/ddove-grill-with-demand` 刚选中的稿）；没有则停并指向 `/ddove-grill`，不进班组。`ddove-wiki-create`、`ddove-fix-up`、`ddove-wiki-change-state` 仍按篇数：只有一篇直接做；多于一篇且点名只做那篇；没点名则停，只问选哪一篇。
- **拆图**交给只读 `.cursor/agents/ddove-plan`。拆票前先写两份公开接口。父会话冻结其中一份，再批准任务图、写 wiki、派单、回收。
- 工人用 Task 拉起 `.cursor/agents/ddove-worker`：一票一个；`paths` 不重叠则同一条父消息里并行多个。prompt 必须带整张任务图要点 + 本票 + 验收原文。
- 每批工人回收后，本批改动路径含 `DDoveMiniGameClient/`（含导表生成的代码）：父会话串行跑 `ddove-unity-pipeline` 步骤 2–3（`editor_status` → `set_autotick --enable true` → `recompile` → 轮询 `recompile_status`）。编译过 = `up_to_date`，或 `completed` 且 `failed` 为 false。不含客户端改动则跳过，回复与评分行写明「本轮无客户端改动，未编译」。工人不跑编译。
- `editor_status` 无应答：停，本轮不过，不弹二选一；入选稿 `## 评分` 记一行「未验证」并列改动路径；提示人开编辑器后重跑 `/ddove-work`。
- 审查 / 评分各一个只读子代理。审查 prompt 带编译结果，编译失败判 FAIL。审查分验收和设计；设计只列三件事，不单独改 PASS/FAIL，不改评分权重。审查不执行命令。
- 过线 = 总分 ≥ 70 且审查 PASS。审查 FAIL 一律不过线，照常记分。
- 交还固定 `STATUS` 块。父会话默认只收 STATUS + 改动路径，不把 diff 全文贴回。
- 工人硬卡：停、交还父会话。不问用户、不自己 `/ddove-grill`、不打软 TODO 继续写。
- 同票失败发**新** Task，最多再派 1 次。
- 父会话写 wiki：读并执行 `ddove-wiki-update`。不问短号。得分追加到入选需求稿的 `## 评分`，不另开文件。按 `draft`+`需求` 开工结束（未过线且已重做，或过线）时，父会话接着写上正式 / 废弃，再给人看产品。回复先写用法篇、说明页、是否符合对齐需求；客户端写运行证据或「未进 Play」；得分表在后。不弹二选一。整份做完由代理在这一拍写上：按职种生成或改写用法篇（同一文件名；只写干什么 / 有哪些接口 / 每个接口干什么；`stable`；`verified` 只写时刻；`tags` 无 `需求`；无 `## 评分`；无「要什么 / 不要 / 验收」；已有同名则改正文，不另开第二份）。职种目录：`策划` → `01-策划`；`程序-前` → `02-程序-前`；`程序-后` → `03-程序-后`；`美术` → `04-美术`；只有 `索引` + `agent` → `00-索引/Agent`。需求稿改为 `deprecated`，写入 `deprecated_at`，连同名 html 搬到 `_archive/需求/`，原路径不留文件。正文留下 `## 要什么`、`## 不要`、`## 评分` 和用法篇链接，不留 `## 验收`、`## 落点`，`title` 仍含「需求稿」。

**不要**

- `ddove-orchestrator`、第二套用户 `/`、把清扫归档做成每篇需求的必经一步。
- `CONTEXT.md`、第四种 `status`。
- 问答里顺手建工程概念篇。
- 拆图子代理写文件；父会话 `update` 对照篇（只点名过期）。
- 自动升 `stable`、自动写 `verified`。
- 扫 `DDoveMiniGameClient/Library`。
- 在 `.cursor/agents/` 里再套一层 markdown。

## 闸门

处理中 = `05-需求` 且 `draft` 且 `tags` 含 `需求`。

1. **改代码没有当前 grill 的那一篇**：停。下一刀 `/ddove-grill`。不数稿。
2. **有当前 grill 的那一篇**：只拆、回写、记分这一篇。当前 grill 是 `/ddove-grill` 刚落的稿，或 `/ddove-grill-with-demand` 刚选中的稿。
3. 入选这一篇没有可执行的验收句：拆图子代理交还后父会话停，再 `/ddove-grill`。不补造验收。
4. 入选这一篇 `## 评分` 最后一行是「未验证」：跳过拆图、批准、派工、回写，只做编译 → 审查 → 评分 → 记分 → 收口。编译用该行列出的改动路径。`rework_used` 从 0 开始。
5. 问答 / 排障：不进班组，也不问选哪一篇。

## 交还（STATUS）

工人：

```text
STATUS: SLICE_DONE | NEED_PATCH | FAIL
票: ...
改动路径: ...
wiki: Concept ID + status
done_when: 满足/不满足
越界: 无/有（路径）
NEED_PATCH: （仅硬卡；选项与建议）
```

审查：`STATUS: PASS | FAIL` + `编译: 过 / 失败 / 未编译`（失败附 `errors`）+ 各验收句判定。  
评分：`STATUS: SCORE` + 表 + 总分 + 是否过线（总分 ≥ 70 且审查 PASS）+ `vN+1`（可空）。  
拆图：`STATUS: PLAN` + 任务图；无验收则 `STATUS: NEED_GRILL`。
