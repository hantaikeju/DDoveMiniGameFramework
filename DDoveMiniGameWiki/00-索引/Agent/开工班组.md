# 开工班组

Concept ID：`/00-索引/Agent/开工班组`。地图：[Agent 总览](/00-索引/Agent/Agent总览.md)。接在 [需求稿工作流](/00-索引/Agent/需求稿工作流.md) 第 3 步。结论与代码冲突以当前代码为准。

目的：多子代理隔离上下文，父会话保持干净。不另开 `/ddove-crew`，不加编排者开环。用户入口仍是 `ddove-work`。不要直接 `/ddove-plan` / `/ddove-worker` 问答。问答 / 排障不写篇、不进班组。

拆图 / 工人 / 审查 / 评分已落 `.cursor/agents/` 与 `ddove-work` 角色卡。

外库 `feature-*` 只学交还协议与上下文隔离，不拷 8 圈编排、单切片串行、热更/导表/Prefab 禁令。

## 目标 / 不做什么

**要**

- `ddove-work` 的「改代码」分支：检索到 `status: draft` 且 `tags` 含 `需求` 的篇则进班组。
- **拆图**交给只读 `.cursor/agents/ddove-plan`。父会话只批准任务图、写 wiki、派单、回收。
- 工人用 Task 拉起 `.cursor/agents/ddove-worker`：一票一个；`paths` 不重叠则同一条父消息里并行多个。prompt 必须带整张任务图要点 + 本票 + 验收原文。
- 审查 / 评分各一个只读子代理。
- 交还固定 `STATUS` 块。父会话默认只收 STATUS + 改动路径，不把 diff 全文贴回。
- 工人硬卡：停、交还父会话。不问用户、不自己 `/ddove-grill`、不打软 TODO 继续写。
- 同票失败发**新** Task，最多再派 1 次。
- 父会话写 wiki：读并执行 `ddove-wiki-update`。得分追加到入选需求稿的 `## 评分`，不另开文件。整份做完才由人跑 `/ddove-wiki-change-state`：按职种生成或改写用法篇（同一文件名；只写干什么 / 有哪些接口 / 每个接口干什么；`stable` + `verified`；`tags` 无 `需求`；无 `## 评分`；无「要什么 / 不要 / 验收」；已有同名则改正文，不另开第二份）。职种目录：`策划` → `01-策划`；`程序-前` → `02-程序-前`；`程序-后` → `03-程序-后`；`美术` → `04-美术`；只有 `索引` + `agent` → `00-索引/Agent`。需求稿改为 `deprecated`，文件不删，正文留下 `## 要什么`、`## 不要`、`## 评分` 和用法篇链接，不留 `## 验收`、`## 落点`，`title` 仍含「需求稿」。

**不要**

- `ddove-orchestrator`、新入口 skill、第二套用户 `/`。
- `CONTEXT.md`、第四种 `status`。
- 问答里顺手建工程概念篇。
- 拆图子代理写文件；父会话 `update` 对照篇（只点名过期）。
- 自动升 `stable`、自动写 `verified`。
- 扫 `DDoveMiniGameClient/Library`。
- 在 `.cursor/agents/` 里再套一层 markdown。

## 闸门

1. **0 篇** `draft`+`需求`：停。下一刀 `/ddove-grill` 或 `/ddove-wiki-create`。
2. **≥1 篇**：进班组。多篇全部入选，按时间加权，冲突听较新篇，合成**一张**任务图。
3. 入选稿没有可执行的验收句：拆图子代理交还后父会话停，再 `/ddove-grill`。不补造验收。
4. 问答 / 排障：不进班组。

## 角色

| 角色 | 跑在哪 | 做 | 不做 |
|------|--------|----|------|
| 拆图 | `ddove-plan` 只读 | 出一张任务图 | 改文件、写 wiki、派工 |
| 写 wiki / 批准 | 父会话 | 批准图；update 入选需求稿；把得分追加到该稿 `## 评分` | 改代码 / 改表；update 对照篇；刀中在 `01`–`04` 生成用法篇；另开评分文件 |
| 调度 | 父会话 | 派 Task；同 `paths` 串行，不重叠并行 | 改图、改稿 |
| 工作 | `ddove-worker` | 只开票上脚本；配表走 `ddove-config` | 改 wiki、改任务图、问用户 |
| 审查 | `ddove-review` 只读 | 对照验收：过 / 不过 | 打分、改文件 |
| 评分 | `ddove-score` 只读 | 用冻结 vN 打分；交 vN+1 增量 | 改 wiki、改代码 |

父会话写 wiki 走 update / create 全文步骤：回 `draft`、摘 `verified`、写 `_log`、跑 `check_wiki.py`。不改 `generated.by`。

## 交还（STATUS）

工人：

```text
STATUS: SLICE_DONE | NEED_PATCH | FAIL
票: ...
改动路径: ...
wiki: Concept ID + status
done_when: 满足/不满足
越界: 无/有（路径）
NEED_PATCH: （仅硬卡；选项与建议）
```

审查：`STATUS: PASS | FAIL` + 各验收句判定。  
评分：`STATUS: SCORE` + 表 + 总分 + 是否过线 + vN+1 增量。  
拆图：`STATUS: PLAN` + 任务图；无验收则 `STATUS: NEED_GRILL`。

## 一轮顺序

```text
检索 draft+需求
    ├─ 0 篇 → 停
    └─ ≥1 篇 → Task 拉 ddove-plan（只读拆图）
         父会话批准（NEED_GRILL 则停）
         调度：Task 拉 ddove-worker（不重叠并行；prompt=图+票+验收）
         父会话只收 STATUS + 路径；按代码回写入选需求稿
         Task 拉 ddove-review / ddove-score
         父会话把得分表追加到入选需求稿的 ## 评分（不新建评分文件）
         低分 → 再拉 ddove-plan 补丁图 + 新 Task 工人，同一次开工只重做 1 轮
         过线且审查过关 → 需求稿仍留在 05-需求，仍带 需求
         整份需求做完 → 人跑 /ddove-wiki-change-state（用法篇三块 + 需求稿留下 ## 要什么、## 不要、## 评分、用法篇链接，不留 ## 验收、## 落点，title 仍含「需求稿」，文件不删）
         重做后仍不过线 → 停，把得分表给人；分数仍写在需求稿上
```

规格中途不改：先分后改尺。低分本身不升正式。对照篇过期只点名。

## 开工评分

Concept ID 预定：`/00-索引/Agent/开工评分`。`type: Playbook`；`tags: [索引, agent]`。正文写 `规格版本: vN`。没有则本轮父会话 `create`；有则当现行尺子，结论仍点名它的 `draft` / `stable`。v1 种子在 `.agents/skills/ddove-work/roles/score.md`。

得分表写进入选需求稿的 `## 评分`，并出现在开工回复里。不每轮建 `Report`，不另开评分文件。过线默认总分 ≥ 70（百分）。尺子条文变了才把 vN+1 写回本篇。

## 验收

1. 无 `draft`+`需求` 时 `ddove-work` 改代码不进班组，并提示 grill / create。
2. 恰有一篇或多篇时进班组；多篇一张图，冲突听较新。
3. 问答 / 排障不写 wiki。
4. 只有父会话改入选需求稿（含 `## 评分`）；尺子条文不变则不改 `开工评分`；`ddove-plan` 只读；对照篇不被 update；刀中不在 `01`–`04` 生成用法篇。
5. 回复有得分表；同一张需求稿里有本轮分数。没有新的评分文件。
6. 低分只重做 1 轮。过线后需求稿仍在 `05-需求` 且仍带 `需求`。整份做完才由人 change-state：用法篇只写干什么 / 有哪些接口 / 每个接口干什么，`stable` + `verified`，`tags` 无 `需求`，无 `## 评分`，无「要什么 / 不要 / 验收」；需求稿改为 `deprecated`，文件不删，正文留下 `## 要什么`、`## 不要`、`## 评分` 和用法篇链接，不留 `## 验收`、`## 落点`，`title` 仍含「需求稿」。职种目录规则不变。
7. 无 `/ddove-crew`、无编排者、无 `CONTEXT.md`、无第四种 `status`。子代理不是用户 `/` 入口。
8. 父会话不粘贴工人 diff 全文。
9. 本篇再当约定：`/ddove-wiki-change-state` 升 `stable`（同步写 `verified`）。
