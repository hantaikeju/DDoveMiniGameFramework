# 需求稿留下要什么不要

Concept ID：`/00-索引/Agent/需求稿留下要什么不要`。入口：[ddove-wiki-change-state](../../../.agents/skills/ddove-wiki-change-state/SKILL.md)。步骤见 [需求稿工作流](/00-索引/Agent/需求稿工作流.md)。

## 干什么

整份需求做完时跑 `/ddove-wiki-change-state`。它按需求稿 `tags` 里的职种生成或改写用法篇，用法篇只写三块。需求稿改成废弃记录，留下当时定过的业务，文件不删。

## 有哪些接口

- `/ddove-wiki-change-state`（目标篇在 `05-需求`，状态升为做完）
- 职种目录
- 用法篇三块
- 需求稿留下的四样

## 每个接口干什么

`/ddove-wiki-change-state` 在目标篇位于 `05-需求` 且这次是整份做完时，不把需求稿本身留成用法。同一文件名写到职种目录。目标目录已有同名篇则改正文并升正式，不另开第二份。

职种目录：`策划` → `01-策划`；`程序-前` → `02-程序-前`；`程序-后` → `03-程序-后`；`美术` → `04-美术`；只有 `索引` + `agent` → `00-索引/Agent`。

用法篇三块只有「干什么」「有哪些接口」「每个接口干什么」。没有需求稿的「要什么 / 不要 / 验收」，没有 `## 评分`。`tags` 无 `需求`。升正式时同步写 `verified`。

需求稿留下的四样：`## 要什么`、`## 不要`、`## 评分`、用法篇链接。不留 `## 验收`，不留 `## 落点`。`status` 改为 `deprecated`。`title` 仍含「需求稿」。得分留在需求稿。清单上该行徽章改为 `deprecated`。
