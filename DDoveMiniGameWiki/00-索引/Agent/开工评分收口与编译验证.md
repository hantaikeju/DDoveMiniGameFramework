# 开工评分收口与编译验证

Concept ID：`/00-索引/Agent/开工评分收口与编译验证`。地图：[Agent 总览](/00-索引/Agent/Agent总览.md)。步骤见 [开工班组](/00-索引/Agent/开工班组.md)。尺子：[开工评分](/00-索引/Agent/开工评分.md)。

[打开说明](开工评分收口与编译验证.html)

## 干什么

开工班组收口时，过线要同时满足总分和审查。每批工人回收后，有客户端改动就由父会话串行编译，结果交给审查。编辑器离线时这一轮停下，重跑只补验证。尺子只在人指出判错时改。

## 有哪些接口

- 过线
- 编译
- 未验证
- 规格增量

## 每个接口干什么

过线 = 总分 ≥ 70 且审查 PASS。审查 FAIL 一律不过线，照常记分。未过线且还没重做：补丁图带上编译 errors，同一次开工重做 1 轮。未过线且已重做，或过线：交得分表，代理接着把用法篇标正式、需求稿标废弃，再给人看产品。编辑器离线停下不写这两篇状态。

编译由父会话做。每批回收后，改动路径含 `DDoveMiniGameClient/`（含导表生成的代码）时，串行跑 `editor_status` → `set_autotick --enable true` → `recompile` → 轮询 `recompile_status`。编译过 = `up_to_date`，或 `completed` 且 `failed` 为 false。失败把 errors 交给审查，审查判 FAIL。不含客户端改动就跳过，回复与评分行写明「本轮无客户端改动，未编译」。工人和审查不跑命令。

未验证：`editor_status` 无应答时停，不弹二选一。入选需求稿 `## 评分` 记一行「未验证」，列出本轮改动路径，提示人开编辑器后重跑 `/ddove-work`。重跑看到最后一行是「未验证」：跳过拆图和派工，只做编译 → 审查 → 评分。这一行不算一轮，`rework_used` 从 0 开始。

规格增量：本轮没提议改尺也满分；提议了必须可执行，并点名是哪一次判错，否则扣。`vN+1` 可空。尺子只在人指出判错时改。各维与权重不动。
