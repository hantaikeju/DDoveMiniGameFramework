# 开篇与清单徽章

Concept ID：`/00-索引/Agent/开篇与清单徽章`。接在 [需求稿工作流](/00-索引/Agent/需求稿工作流.md)，不另写第二份流程。地图：[Agent 总览](/00-索引/Agent/Agent总览.md)。维护 skill 走 `ddove-writing-for-agents`。

`status` 只乘 YAML。问答里点名 draft 不要抄进篇首。新建仍 `draft` 写完再升一次；不是 create 完就 change-state 再 update。

过期对照（本刀不改正文）：[OKF约定](/00-索引/OKF约定.md) 仍写「不要日常重生成各层 index」，未开「change-state 改本篇那一行」例外。[需求稿工作流](/00-索引/Agent/需求稿工作流.md) 未写开篇禁令与升正式摘 `需求`。[DDoveAudio](/02-程序-前/DDoveAudio.md) 开篇仍写 draft，存量另走 `/ddove-wiki-update`。

## 要

- `ddove-wiki-create` / `ddove-wiki-update`：正文禁止写「本篇是 draft」「本文 `status: draft`」「不当发布依据」这类自报。阶段只看 frontmatter。
- `/ddove-wiki-change-state` 升 `stable`：同步写 `verified`；**摘掉** `需求` tag（处理中结束）。主题不再用这个字。
- 同一刀只改**本篇所在清单那一行**的 type / status / `需求` 徽章（`index_<短号>.md`、本目录 `index.md`、或 `00-索引/index.md` 里挂了就改那行）。不重生成整份清单，不改根 `/index.md`。
- 改正文仍回 `draft`、摘 `verified`。再升正式另跑 change-state。不把两刀合成一条。

## 不要

- 开篇或结论段复述 YAML 的 `status`。
- change-state 改正文、扫全库徽章、重写整份 `index_*`。
- 错字 / 擦脏句可以一直留在 `stable`。
- 自动升 `stable`、第四种 `status`。
- 本稿验收清存量（Audio 开篇、已脏清单行）。

## 验收

1. 按 create / update 新建或改正文后，篇首没有 `status: draft` / 「本篇是 draft」/ 「不当发布依据」。
2. change-state 升 `stable` 后：该篇 `tags` 无 `需求`；挂着它的那一行徽章与当前 `type` / `status` / 是否含 `需求` 一致。
3. 同一次 change-state 不改其它行、不重写整份清单。
4. update 仍把 `status` 写回 `draft` 并删 `verified`；回复下一刀仍是 change-state。
5. 无第四种 `status`；无自动升正式。
6. 本篇再当约定：人跑 `/ddove-wiki-change-state` 升 `stable`。
