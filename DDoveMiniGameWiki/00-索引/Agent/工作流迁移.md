# 工作流迁移

Concept ID：`/00-索引/Agent/工作流迁移`。地图：[Agent 总览](/00-索引/Agent/Agent总览.md)。

本仓的 AI 工作流按引擎无关的一层设计。换 Godot（或别的引擎）**拷 AI 层 + 空壳**，不要拷 `DDoveMiniGameWiki/02-程序-前` 里的 DDoveRes / YooAsset / UniTask。

## 带走 / 留下

| 带走（流程） | 留下（本工程） |
|--------------|----------------|
| 仓库根 `SPEC.md`、`AGENTS.md` | `DDoveMiniGameClient/`、`Library`、UPM |
| `DDoveMiniGameWiki/00-索引/` 根：OKF约定、检索指南、来源说明、升级与合规、整理人 | `DDoveMiniGameWiki/01`–`04` 里已有业务篇 |
| `DDoveMiniGameWiki/00-索引/Agent/` 全文 | 旧路径 Stub（show-me / 需求稿） |
| `.agents/skills/`（及 `.cursor/skills/` 同步份） | skill 正文里的 `DDoveMiniGameClient/Library`、Unity 触发词 |
| `DDoveMiniGameTools/check_wiki.py`、`.github/workflows/wiki-check.yml` | `DDoveMiniGameWiki/_log/` 旧日明细（可空着新开） |
| `DDoveMiniGameWiki/index.md`、`DDoveMiniGameWiki/log.md` 骨架 | 个人 `~\.cursor\skills\`（本机已有，不必拷） |

`01`–`04` 只建空目录 + `index.md` + 你的 `index_<短号>.md`，不带旧篇。

## 步骤

1. **新仓空壳**：建 `DDoveMiniGameWiki/00-索引/`、`DDoveMiniGameWiki/00-索引/Agent/`、`DDoveMiniGameWiki/01`–`04`、`DDoveMiniGameWiki/_log/`。拷上表「带走」列。根 `DDoveMiniGameWiki/index.md` 的 `okf_version` 与本仓一致即可。
2. **改前缀**：全文替换仓库 skill 名 `ddove-` → 新品牌（如 `gdove-`）。文件夹名、`AGENTS.md`、`Agent总览` 一起换。个人 skill（show-me）不改名、不进新仓。
3. **改禁区**：`AGENTS.md` / `*-wiki` skill 里的 `DDoveMiniGameClient/Library` 换成新引擎生成物（Godot：`.godot/`、`.import/`）。`description` 触发词改成该引擎的打包 / 场景 / 资源说法。
4. **整理人**：`DDoveMiniGameWiki/00-索引/整理人.md` 留下短号表，按新仓人改一行。
5. **第一场**：`/新前缀-grill` 对齐「这个引擎框架要什么」→ 落 `draft`+`需求` 进 `02-程序-前`（或你改名后的职种目录）→ 再写代码。不要从本仓拷 Unity 结论当 Godot 权威。
6. **检查**：`py -3 DDoveMiniGameTools/check_wiki.py`。

完成：新仓能 `/…-wiki` grep 到约定与 Agent 篇，且 `01`–`04` 没有 Unity 业务篇。

## 下次更快

若还要第三套引擎，把「带走」列收成独立模板仓（skill 前缀用中性名如 `okf-`），Unity / Godot 仓只各自养 `01`–`04`。未做模板之前，按上面 6 步复制即可。
