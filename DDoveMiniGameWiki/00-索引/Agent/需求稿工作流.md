# 需求稿工作流

Concept ID：`/00-索引/Agent/需求稿工作流`。地图：[Agent 总览](/00-索引/Agent/Agent总览.md)。

`status` 只允许 `draft` / `stable` / `deprecated`。需求「处理中」= 篇在 `05-需求`，且 `draft` + `tags` 含 `需求`。正文不自报 `status`，细则：[开篇与清单徽章](/00-索引/Agent/开篇与清单徽章.md)。

需求稿一律落 `05-需求`。`tags` 含目标职种（`策划` / `程序-前` / `程序-后` / `美术`，或 AI 用法的 `索引` + `agent`）以及 `需求`。`01`–`04` 与 `00-索引/Agent` 只放用法篇。

每一轮开工的得分表追加到该需求稿的 `## 评分`。不另开评分文件。尺子仍是 [开工评分](/00-索引/Agent/开工评分.md)；只有尺子条文要变才改那一篇。

## 步骤

1. `/ddove-grill`：拷问到 frontier 空、你确认对齐。
2. 落稿：grill 末步或 `/ddove-wiki-create`。目录 `05-需求`；`type: Playbook`；`status: draft`；`tags` 按上一节。开篇不写「本篇是 draft」。落在 `05-需求` 时调用 `ddove-show-me`（种类「要什么不要」），开篇加同目录相对链接，打开同名 `.html`。
3. 按稿改代码或补正文。问答 / 改代码走 `ddove-work`（先检索），结论须标明 draft。得分写进这篇的 `## 评分`。已有用法篇过期走 `/ddove-wiki-update`。刀进行中不在职种目录新建用法篇。
4. 整份需求做完：`/ddove-wiki-change-state`。不把需求稿本身留成用法。按 `tags` 里的职种生成或改写用法篇：`策划` → `01-策划`；`程序-前` → `02-程序-前`；`程序-后` → `03-程序-后`；`美术` → `04-美术`；只有 `索引` + `agent` → `00-索引/Agent`。用法篇同一文件名，只写三块：干什么、有哪些接口、每个接口干什么。没有需求稿的「要什么 / 不要 / 验收」，没有 `## 评分`。`tags` 无 `需求`。`status: stable`，同步写 `verified`。目标目录已有同名篇则改正文并升 `stable`，不另开第二份。需求稿改为 `deprecated`，文件不删。正文留下 `## 要什么`、`## 不要`、`## 评分`、用法篇链接和打开同名 `.html` 的链接；不留 `## 验收`、`## 落点`。`title` 仍含「需求稿」。得分留在需求稿。用法篇挂到目标目录的 `index_<短号>.md`；需求稿那一行徽章改为 `deprecated`。整份做完时调用 `ddove-show-me` 两次：用法篇旁画三块并在篇内加链接；再按最终「要什么 / 不要」重画需求稿那份 HTML。
