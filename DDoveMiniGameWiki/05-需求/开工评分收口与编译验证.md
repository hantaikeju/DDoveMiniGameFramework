# 开工评分收口与编译验证（需求稿）

用法篇：[开工评分收口与编译验证](/00-索引/Agent/开工评分收口与编译验证.md)。

[打开说明](开工评分收口与编译验证.html)

## 要什么

1. **过线 = 总分 ≥ 70 且审查 PASS。** 审查 FAIL 一律不过线，照常记分，走同一次开工的那 1 次重做；重做后仍 FAIL 就停，交得分表。收口只剩三条：
   - 未过线且 `rework_used == 0`：重做。
   - 未过线且已重做：停，交得分表。
   - 过线：交得分表。
   后两条都是开工结束，弹二选一，选项只有 `/ddove-fix-up` 与 `/ddove-wiki-change-state`。编辑器离线停下不算开工结束，不弹。
2. **父会话跑编译。** 每批工人回收后，本批 `改动路径` 里有 `DDoveMiniGameClient/` 下的文件（含导表生成的代码），父会话串行跑一轮 `ddove-unity-pipeline` 步骤 3：`set_autotick --enable true` → `recompile` → 轮询 `recompile_status`。没有客户端改动就跳过，回复与评分行写明「本轮无客户端改动，未编译」。
3. **编译结果交给审查。** 编译过 = `status` 为 `up_to_date`，或 `completed` 且 `failed` 为 false。编译结果写进审查 prompt。编译失败：`errors` 交给审查，审查判 `FAIL`，按第 1 条重做；补丁图带上这些 `errors`。
4. **编辑器离线就停。** `editor_status` 无应答：本轮不过，不弹二选一。在这一篇需求稿 `## 评分` 记一行「未验证」，列出本轮改动路径，回复提示人开编辑器后重跑 `/ddove-work`。
5. **重跑只补验证。** `ddove-work` 开工时看到这一篇 `## 评分` 最后一行是「未验证」：跳过拆图和派工，直接编译 → 审查 → 评分。「未验证」行不算一轮；重跑时 `rework_used` 从 0 开始。
6. **尺子不再每轮必交 vN+1。** 「规格增量」10 分改判：本轮没提议改尺也满分；提议了就必须可执行，并点名是哪一次判错，否则扣。其余各维与权重不动。尺子只在人指出判错时改。`STATUS: SCORE` 的 `vN+1` 栏改为可空。
7. `.agents/skills/` 与 `.cursor/skills/` 里要改的文件各改一份，两份一致。

## 不要

- 场景、Prefab、运行行为的验证（本篇只到编译）
- 工人自己跑 recompile，或审查子代理执行命令
- 修旧文档：v12 漂移、已废弃需求稿里的旧评分表、各处重复的选篇规则
- 脚本化闸门、精简写法（留给后面的需求稿）
- 新的 `/` 入口、第四种 `status`、另开评分文件
- 改评分各维与权重（「规格增量」只改判法）
- 自动升 `stable`
