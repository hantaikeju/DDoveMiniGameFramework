# 对齐后接着做完（需求稿）

用法篇：[对齐后接着做完](/00-索引/Agent/对齐后接着做完.md)。

[打开说明](对齐后接着做完.html)

## 要什么

grill 里人把需求对接清楚并确认对齐。对齐之后，同一条对话里代理接着做完，人不为状态另敲命令。

1. 代理把对齐结果写成 `05-需求` 需求稿，并按这篇改 skill 和 wiki。
2. 文件做完，代理立刻把用法篇标成正式（同步写 `verified`）、需求稿标成废弃。不等人先点头。
3. 然后给人看产品：用法篇、说明页、这次改了什么。改了客户端时，再加上行为是否符合对齐过的需求。
4. 产品不对：人用自己的话指出要改的地方。代理把用法篇和需求稿都回到处理中，改完再写成正式 / 废弃，然后再给人看。
5. `/ddove-wiki-create`、`/ddove-fix-up`、`/ddove-wiki-change-state` 从人的下一步里拿掉。这三步的手续仍由代理在对齐后的对话里执行。

人只做两件事：grill 里把需求对接清楚；最后看产品，说可以，或指出还要改哪里。

## 不要

- 人自己改 `draft` / `stable` / `deprecated`
- 对齐之后停下来等人敲落稿或改状态
- 问答和排障走这套收口
- 把仍是 `draft` 的 `开工班组`、`开工评分` 在这一篇里升成正式
