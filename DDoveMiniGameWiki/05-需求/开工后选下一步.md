# 开工后选下一步（需求稿）

用法篇：[开工后选下一步](/00-索引/Agent/开工后选下一步.md)。

[打开说明](开工后选下一步.html)

## 要什么

需求稿链的收口：

1. `/ddove-grill` 对齐完成。下一步只报 `/ddove-wiki-create`。本步不写需求稿。
2. `/ddove-wiki-create` 落在 `05-需求` 且 `tags` 含 `需求`。下一步只报 `/ddove-work`。
3. `/ddove-work` 按一篇 `draft`+`需求` 开工结束。回复用一次选择问完，选项只有 `/ddove-fix-up`、`/ddove-wiki-change-state`。不报 `/ddove-next`。本步不判断这篇范围做完没有，不代跑其中任何一条。问答和排障不弹这题。
4. `/ddove-fix-up`：修复。`disable-model-invocation: true`。只在用户调用 `/ddove-fix-up` 时用。用户指出还要修的部分。下一步只报 `/ddove-work`。本步不改代码、不改篇、不改 `status`，不代跑开工。两份：`.agents/skills/ddove-fix-up/SKILL.md` 与 `.cursor/skills/ddove-fix-up/SKILL.md`。
5. `/ddove-wiki-change-state` 把 `05-需求` 一篇整份做完。回复标明这是最后一步，不再报下一指令。

去掉 `/ddove-next`。`.agents/skills/ddove-next/` 与 `.cursor/skills/ddove-next/` 不再保留。开工结束不再多一跳。

同一规则写进这些收口：

- `ddove-grill`：对齐后的下一步是 `/ddove-wiki-create`。末步不读取、不执行 `ddove-wiki-create`。
- `ddove-wiki-create`：新建的是 `05-需求` 需求稿时，回复的下一步是 `/ddove-work`。
- `ddove-work`：按需求稿开工结束时，选项只有 `/ddove-fix-up` 与 `/ddove-wiki-change-state`。不报 `/ddove-next`。问答和排障不弹这题。
- `ddove-wiki-change-state`：`05-需求` 整份做完时，回复写明这是最后一步。
- `ddove-help` 的整图与选路写上 `/ddove-fix-up`，并去掉 `/ddove-next`。
- [需求稿工作流](/00-索引/Agent/需求稿工作流.md)、[Agent 总览](/00-索引/Agent/Agent总览.md)、[开工班组](/00-索引/Agent/开工班组.md)、仓库根 `AGENTS.md` 改成这条收口。`.agents/skills/` 与 `.cursor/skills/` 里要改的技能各改一份。

## 不要

- `/ddove-work` 结束时由代理判断「还没做完」或「已经做完」
- 把落稿和 `/ddove-wiki-create` 写成两条路
- grill 对齐后在内部执行 create
- 开工结束只报 `/ddove-next`
- 保留 `/ddove-next` 作为修复和 change-state 前面的一跳
- `/ddove-fix-up` 里改代码、改篇或改 `status`
- 开工结束的选择再加第三个选项
- 问答或排障结束时弹出这题
- 改 `/ddove-wiki-update` 已有的下一刀
- 自动升 `stable`
