# ddove-show-me

个人画图仍是本机 `/show-me`，见 `DDoveMiniGameWiki/00-索引/Agent/show-me安装.md`。本技能只写一张静态 HTML。用法篇三块见 `DDoveMiniGameWiki/00-索引/Agent/需求做完生成接口总结.md`。需求稿留下的要什么、不要见 `DDoveMiniGameWiki/00-索引/Agent/需求稿留下要什么不要.md`。不把 `/show-me` 拷进仓库，不新建「查看 HTML」指令。

调用方传入目标 `.md` 路径，以及种类「说明页」。只认这一种。一次调用写一张。链接由调用方写进该 `.md`。本技能不改那份 `.md`。

谁来调：`/ddove-wiki-create` 落 `05-需求` 新稿时，种类「说明页」。`/ddove-wiki-change-state` 把 `05-需求` 整份做完时，对用法篇、再对需求稿各调一次，种类都是「说明页」。`/ddove-wiki-update` 改正文且旁边已有同名 HTML 时，种类「说明页」重画这一张；没有同名 HTML 的不补。`ddove-work` 过线不调用。不扫描仓库去给已有篇补 HTML。

## 步骤

1. **入参**：目标 `.md` 已在仓库里，种类是「说明页」。一次一个路径。不是「说明页」则停，不写 HTML。完成：路径存在，种类是「说明页」。
2. **文件名**：HTML 与该 `.md` 同目录，主文件名与该 `.md` 相同，扩展名 `.html`。主文件名只取自 `.md` 文件名。YAML `title` 含「需求稿」时，文件名仍用 `.md` 主文件名。完成：输出路径已定。
3. **取块**：读该 `.md` 正文，跳过 YAML frontmatter。以调用当时的正文为准。篇类型：路径在 `05-需求/` 或 YAML `title` 含「需求稿」→ 需求稿；否则 → 用法篇。
   - 需求稿：`## 要什么`、`## 不要`
   - 用法篇：`## 干什么`、`## 有哪些接口`、`## 每个接口干什么`
   每块收到下一个同级或更高级标题为止。缺任一要求的标题则停，不写 HTML，把缺的标题交还调用方。完成：要画的块已齐，或已停。
4. **写页**：UTF-8 单文件，样式内联，无外链资源，无脚本（含 Mermaid 脚本）。文件开头是 `<!DOCTYPE html>`，不写 YAML，不写 `type` / `status` / `tags`。页内主标题用该篇第一个 `#` 标题；没有则用主文件名。
   用 HTML / CSS / SVG 画结构，像本机 `/show-me`：只留当前篇要看懂的边界、调用、纳入与排除。标签用篇里的真实名字（skill、路径、标题），压成短语。不逐字贴正文，不把段落、列表、围栏原样转成 HTML。
   - 需求稿：按「要什么 / 不要」画纳入与排除、落点、谁来调。一页分区图，不是左右两栏原文。
   - 用法篇：按「干什么 / 有哪些接口 / 每个接口干什么」画职责、节点、谁调谁。一页调用图，不是三张原文卡片。
   整页可滚动，桌面与窄屏都能看。页上没有分步按钮，也没有按步隐藏的内容。同路径已有 `.html` 则整文件重写。完成：该 `.html` 已写；开头不是 `---`；页是结构图，不是原文换皮。
5. **收尾**：不改目标 `.md`，不改其它篇，不把 HTML 写入清单或 log。不读、不改 `~\.cursor\skills\show-me\`。仓库里的技能目录是 `ddove-show-me`，不要建成名为 `show-me` 的个人技能。完成：磁盘上只多了或更新了这一张 HTML。

完成：调用方给出的那一个 `.md` 旁边有同主文件名 `.html`；种类是「说明页」；取块按篇类型；页是结构图不是原文换皮；无概念 frontmatter；目标 `.md` 的链接仍由调用方写。
