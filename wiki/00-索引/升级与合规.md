# 升级与合规

权威规范 = 仓库根 [`SPEC.md`](../../SPEC.md)。不要拷第二份进 `wiki/`。

## 何时升级

官方发布新 SPEC → 整文件覆盖仓库根 `SPEC.md` → 主动调用 skill `mgf-okf-upgrade`。

日常问答只走 `mgf-wiki`，不读整份 SPEC，不改合规字段。

## 升级 skill 做什么

1. 从当前 `SPEC.md` 抽出版本（标题 / Versioning 节），对比 `wiki/index.md` 的 `okf_version`。
2. **先检查、再改**：输出违规清单，确认后才动文件。
3. 对照 SPEC 合规条款：概念缺 frontmatter / 缺 `type`；误把 `index.md`、`log.md` 当概念；分类 `index.md` 不该有 frontmatter；根 `index.md` 只能有 `okf_version`。
4. 对照 SPEC 的 Breaking / Additive：迁移废弃字段；更新 `OKF约定.md` 里过时句子。
5. 把根 `index.md` 的 `okf_version` 改为 SPEC 当前版本。根清单只挂目录。业务目录的篇目在 `index_<短号>.md`，不要摊进职种 `index.md` 或根清单。在当天 `_log/log_YYYY-MM-DD.md` 顶部记一条，并保证根 `log.md` 有该日索引。
6. **不重写** 概念正文，除非旧字段被规范废弃。

跳过：`_tools/`、`_spec/`、`_log/`、`.obsidian/`、仓库根 `SPEC.md`、`DDoveMiniGameClient/`。
